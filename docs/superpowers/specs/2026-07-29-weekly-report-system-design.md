# 营销运作部周报系统 — 完整设计规格

> 日期：2026-07-29
> 状态：已确认，待实施

---

## 1. 业务背景

营销运作部约 60 人，分 4 个业务模块，每周通过邮件提交周报（Excel/PPT）。
目标：自动化采集 → 按模块合并 → 统一汇总 → 邮件投递给负责人和领导。

## 2. 业务模块与模板

| 模块 | 人数 | 格式 | 模板特征 |
|------|------|------|----------|
| 国内运营商 | ≤10 | Excel | 6 列：序号/重点项目/子目标/本周进展/下周计划/风险求助 |
| 营销运营部 | ~15 | Excel | 5 列：业务模块/本周进展/下周计划/问题反馈/备注 |
| 销售部 | 30+ | Excel | 三段式（日常工作/质量供应问题/竞品信息），14 列 |
| 海外 BD | ~10 | PPT | 独立 PPT 文件，跨时区 |

## 3. 角色与权限

| 角色 | 上传 | 审核 | 团队查看 | 周报库可见 | 系统管理 |
|------|------|------|----------|-----------|----------|
| member（成员） | ✅ | - | - | 本人历史 | - |
| leader（负责人） | ✅ | - | 本团队 | 本团队+汇总 | - |
| admin（管理员） | ✅ | ✅ | 全部 | 全部 | ✅ |
| superior（领导） | - | - | 全部 | 全部 | - |

## 4. 审核与截止时间

- **审核流程**：成员提交 → 管理员审核（approved/rejected），单级
- **截止时间**：各模块不同截止时间，后续具体配置
- **当前默认**：周日 23:59

## 6. 模块合并器设计

### 6.1 合并器接口约定

每个合并器完成合并后，向通用汇总层暴露：

```python
{
    "module_name": str,          # 模块名称
    "total_people": int,         # 应提交人数
    "submitted_count": int,      # 已提交人数
    "submission_rate": str,      # 提交率（百分比字符串）
    "risk_items": list[str],     # 风险项列表
    "key_projects": list[str],   # 重点项目列表
    "output_file": str,          # 汇总文件路径
    "deadline_passed": bool,     # 截止是否已过
}
```

### 6.2 国内运营商合并器

**输入**：N 份 Excel（每人一个 Sheet，6 列模板）
**处理**：
1. 识别每个文件，提取含数据的工作表
2. 去除模板空行（仅保留有内容的数据行）
3. 合并为单一 Excel

**输出文件结构**：
```
国内运营商_周报汇总_YYYYMMDD.xlsx
├── 📑 目录（超链接跳转至各人 Sheet）
├── 📊 本周分析（提交率/风险聚类/重点项目/工作量）
├── 张三（仅数据行，去空行）
├── 李四
└── ...
```

**已有基础**：合并器初版代码存在于 `merger/excel_merger.py`。

### 6.3 营销运营部合并器

**输入**：N 份 Excel（每人一个 Sheet，5 列模板）
**处理**：与 6.2 逻辑相同，列名按配置读取
**输出结构**：与 6.2 相同

**设计决策**：与国内运营商共用合并引擎，模板差异通过配置驱动。

### 6.4 销售部合并器

**输入**：N 份 Excel（每人一个 Sheet，三段式结构）
**处理**：
1. 识别 3 个独立区块的位置（按行偏移或区块标题）
2. 每个区块独立提取和去空行
3. 按区块分表合并

**输出文件结构**：
```
销售部_周报汇总_YYYYMMDD.xlsx
├── 📑 目录
├── 📊 本周分析
├── 📋 日常工作（全员 Section 1 纵向拼为一张大表）
├── ⚠️ 质量供应问题（全员 Section 2 纵向拼为一张大表）
├── 🔍 竞品信息（全员 Section 3 纵向拼为一张大表）
└── 原始数据备份（保留每人的完整 Sheet，备查）
```

**关键挑战**：
- 30+ 人 → 大表行数多，需验证性能
- 区块位置识别：依赖模板固定行偏移或标题文本匹配
- 空行可能由合并单元格产生，需正确处理

### 6.5 海外 BD 合并器

**输入**：N 份 PPT 文件
**处理**：
1. 统一字体（中文 → 等线，英文 → Arial）
2. 每人幻灯片前插入分隔页（标注姓名）
3. 按人员顺序拼接为一个 PPT

**输出**：`海外BD_周报汇总_YYYYMMDD.pptx`

**阶段范围**：本期只做合并，不做内容分析。分析项后续追加。

## 7. 通用汇总层

**输入**：4 份模块接口摘要数据
**输出**：

### 四模块总汇总 Excel
```
四模块周报总汇总_YYYYMMDD.xlsx
├── 📊 执行摘要（首页）
│     ├── 整体提交率
│     ├── 各模块提交一览表（应提交/已提交/提交率/风险数）
│     ├── 本周重点事项（跨模块汇总）
│     └── 风险关注（Top 风险项）
├── 📑 国内运营商（引用或嵌入）
├── 📑 营销运营部
├── 📑 销售部
└── 📑 海外 BD
```

### 邮件正文摘要
- 各模块负责人：提交率 + 风险数 + 请查收附件
- 领导：整体提交率 + 需关注的模块 + 风险概况 + 请查收附件

## 9. 周报库

**新增页面**：`📚 周报库`

**数据模型**（扩展现有 `submissions` 和 `weekly_summaries` 表）：

```sql
-- 周报库归档索引表
CREATE TABLE report_archive (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    week_start TEXT NOT NULL,
    week_end TEXT NOT NULL,
    module_id INTEGER,
    file_type TEXT NOT NULL,     -- 'individual' | 'module_summary' | 'total_summary'
    file_path TEXT NOT NULL,
    user_id INTEGER,             -- 仅 individual 类型有值
    created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
    FOREIGN KEY (module_id) REFERENCES modules(id),
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

**查看权限**：

| 角色 | 可见范围 |
|------|----------|
| member | `file_type='individual' AND user_id=本人` |
| leader | 本团队 `individual` + 本模块 `module_summary` |
| admin/superior | 全部 |

**交互**：
- 按周筛选（下拉选择历史周期）
- 个人周报列表
- 汇总文件列表 + 下载
- 在线预览（Excel 以表格渲染，PPT 提供下载链接）
